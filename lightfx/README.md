# Starglow 星芒 / Shine 放射光束 · 0.1 本地测试版

新增两款Windows x64 Photoshop原生滤镜，目前只在本地开发和测试，未提交GitHub或添加到Releases。首版 0.1 仅新增这两款；后续本地候选已为原十九款接入公共快速预览。当前说明和验证见[公共预览说明](../docs/ADAPTIVE_PREVIEW.md)，Shine 原文件继续保留。

- **Starglow 星芒**：参考Trapcode Starglow公开参数，以八方向光刺扩散高光。支持方向长度、整体旋转、三组单色／三色／五色色谱、各方向色谱分配、源颜色、阈值和柔和过渡。
- **Shine 放射光束**：参考Trapcode Shine公开参数，从二维光源中心生成放射光束。支持光束长度、增强、衰减、色谱和源颜色。PS没有合成灯光系统，因此保留二维光源。

两款共用圆形提取范围、静态闪烁纹理、细节／相位／循环／随机种子、相加／滤色／合成、源与光效不透明度、效果混合和保留源透明度。参考范围中心与Shine光源中心独立。

两款均支持RGB8／16／32、蓝色无边框单项重置、全部重置、中英文、主题／DPI、取色及智能滤镜完整参数保存。每款保存92个效果字段，另有保存版本与身份字段。先将目标图层转为智能对象，再应用并保存PSD，可重开编辑独立实例。

## 拖动与预览

预览区**按住右键拖动中心**，左键拖动平移，滚轮缩放。Shine直接移动光源；Starglow启用圆形范围后可移动范围中心。

“交互快速预览”默认开启：拖动参数时使用最长边不超过256像素的源图与高光缓存，停止变化约180毫秒后自动计算完整质量结果。界面明确标记交互／完整质量；可关闭该选项直接等待完整质量预览。确认后始终以原始分辨率、所选采样质量重新计算，不把交互草图写入图层或PSD。

新调度器合并排队请求，提交参数不等待工作线程退出；进行中的草图可以完成并显示，过期的完整质量任务取消。高光提取结果按相关参数缓存，Shine移动光源不会重复提取。高光先在原尺寸提取再按能量缩小，避免小亮点因先缩图再阈值而消失。宿主读取、界面和纹理上传仍在主线程；后台只处理冻结的CPU数据。

首版 0.1 历史 CPU 基准（本机，1536×1024，已缓存提取；当前 Starglow 已更新）：Starglow交互约6.2ms／完整约108ms，Shine交互约5.5ms／完整约92ms。该数据不含第一次源图读取／提取、显示上传或窗口刷新，不承诺任意尺寸与硬件固定帧率。此版本未加入GPU效果计算。

## 实现与限制

星芒采用定向递归指数核，常用八方向按独立扫描线并行，任意旋转使用剪切扫描并仅在进出时重采样，避免递归插值扩散。Shine在对数半径空间倍增积累，用5／6／7遍处理近似32／64／128个光束样本，光束长度不增加遍数。核函数、阈值、着色和随机纹理为独立实现，尚未进行原版插件同源图逐像素校准，不保证与Trapcode相同细节。

完整源图最多16,777,216像素，输出受PS给定的滤镜范围／画布限制，不会自动扩展画布。极端HDR结果限制在有限float范围。部分着色和混合采用本项目的数值模型。相位表示静态纹理变化，不包含时间线播放、AE灯光或Mocha跟踪。

## 构建与验证

```powershell
./build.ps1 -Module lightfx
./build.ps1 -Module lightfx -CoreOnly
```

依赖与其余模块一致，先建立native共享库。输出为`lightfx/build/ZaYuStarglow.8bf`和`ZaYuShine.8bf`。本地证据在`evidence/lightfx-v01`，不属于公开源码资产。

验证包含解析脉冲响应、旋转／边界、HDR／Alpha、缓存与直接完整计算逐字节一致、保持高光能量的草图、并行一致性、取消和队列调度；实际DLL验证RGB8／PS16／HDR32、选区／填充保护、透明度与旧／新坐标；生产面板验证连续拖动时出图、停止后的完整质量、重置、取消、中英文和旧DPI分支。智能滤镜宿主测试脚本为`tests/host_qa.jsx`与`tests/run-host.ps1`。
